# Как устроен Пульт

[English](ARCHITECTURE.md) · назад к [README](README.ru.md)

Пульт — один небольшой демон на твоём компьютере, который стоит **рядом** с ИИ-агентами, а не перед ними. Он слышит
каждую сессию Claude Code через её хуки; запускает свои сессии через Agent SDK — на моделях Claude или на модели
другого производителя по твоему ключу; просит у Codex второе мнение по собственному протоколу Codex; и по желанию
пишет в открытые вкладки VS Code через обёртку процесса. У каждого агента остаются своя программа, свой вход и своя
связь с производителем. Сам Пульт говорит только с Bot API Telegram и с посредником на твоём сервере (по желанию),
и оба соединения идут с компьютера наружу. **На компьютере ничто не слушает сеть.**

## Общая схема

```mermaid
flowchart LR
  subgraph PC["Твой компьютер"]
    direction TB
    TAB["вкладки VS Code,<br/>сессии в терминале"] -->|"хуки: 8 событий"| HOOK["pult_hook.py"]
    HOOK -->|"локальный сокет"| D(["pultd<br/>демон"])
    D <-->|"локальный сокет"| WRAP["обёртка вкладок<br/>pult_tab.py"]
    WRAP <-->|"stream-json, байт в байт"| CCT["Claude Code<br/>во вкладке VS Code"]
    D -->|"Agent SDK"| CCS["Claude Code<br/>сессии с телефона"]
    D <-->|"app-server, только чтение"| CX["Codex<br/>второе мнение"]
    LOGS[("транскрипты<br/>~/.claude/projects")] -.->|"только чтение"| D
    D --- DB[("state.db")]
  end
  subgraph SRV["Твой сервер, по желанию"]
    R["relay.py<br/>ничего не хранит"]
  end
  subgraph TG["Telegram"]
    API["Bot API"]
    APP["твоя группа, тема на проект<br/>+ Mini App"]
  end
  D -->|"long polling, наружу"| API
  API <--> APP
  APP -->|"wss /pult/ws"| R
  D -->|"wss /pult/agent, наружу"| R
  CCT --> ANT["Anthropic<br/>твоя подписка"]
  CCS --> ANT
  CCS -.->|"модель другого производителя"| VEN["DeepSeek · GLM · Kimi<br/>твой ключ"]
  CX --> OAI["OpenAI<br/>твой вход в ChatGPT"]
```

| Часть | Что это | Почему так |
|---|---|---|
| **pultd** | демон на Python asyncio: launchd на macOS, пользовательская служба systemd на Linux, задание при входе на Windows | один владелец, одно место, где лежат состояние и токен бота |
| **pult_hook.py** | команда, которую Claude Code запускает на `SessionStart`, `UserPromptSubmit`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `StopFailure`, `SessionEnd` и `PermissionRequest`; только стандартная библиотека. Unix-сокет, а на Windows — 127.0.0.1 с ключом в файле, который читаешь только ты | он работает внутри *каждой* сессии на компьютере, поэтому должен быть крошечным и никогда не падать громко |
| **pult_tab.py** | обёртка `claudeCode.claudeProcessWrapper` (по желанию) между расширением VS Code и Claude Code | единственный способ положить сообщение в уже открытую вкладку |
| **Agent SDK** | сессии из Telegram и приложения — твой же Claude Code в папке проекта, по умолчанию в его режиме разрешений `auto` (`PULT_PERMISSION_MODE`) | те же настройки, тот же системный промпт, та же подписка, что в терминале |
| **модель другого производителя** | DeepSeek, GLM и Kimi отвечают по собственному протоколу Claude Code на своём адресе: сессия, которую запускает Пульт, получает этот адрес, твой ключ и модели производителя по ролям (`pult_vendors.py`) | тот же Claude Code, хуки и карточки — другая только модель; только в разрешённом проекте и никогда без ключа |
| **Codex** | агент OpenAI — там, где стоит ChatGPT для Mac или команда `codex`; Пульт ведёт его по протоколу `app-server` (JSON-RPC) в песочнице только для чтения, которая ничего не спрашивает, по одному ревью за раз (`pult_codex.py`) | второе мнение от другого производителя — по твоему же входу в ChatGPT; своих ключей Пульт ему не даёт |
| **relay.py** | посредник WebSocket на небольшом Linux-сервере (~50 МБ памяти) | Telegram открывает Mini App только с публичного HTTPS; компьютер остаётся закрытым |
| **Mini App** | Preact + htm, без сборки, раздаётся посредником | полный экран на телефоне: переписка, ответы, новые задачи, расход |

## Запрос разрешения, отвеченный с телефона

Хук и окно в VS Code идут наперегонки. Claude Code берёт первый ответ и не замечает поздний, поэтому можно
ответить в любом месте, и ничего не зависнет.

```mermaid
sequenceDiagram
  autonumber
  participant CC as Claude Code<br/>(вкладка VS Code)
  participant H as pult_hook.py
  participant D as pultd
  participant T as Telegram
  actor You as Ты, с телефона
  CC->>H: PermissionRequest: команда и её параметры
  H->>D: событие — и ждёт решения
  D->>T: ✋ команда целиком, Разрешить / Отклонить
  Note over CC: окно в VS Code тоже открыто
  You->>T: Разрешить
  T->>D: нажатие кнопки
  D->>H: allow
  H->>CC: решение — выводом хука
  Note over CC,H: решает первый ответ, поздний не замечается
```

Если демон не запущен, хук сразу выходит без вывода, и Claude Code показывает своё окно, будто Пульта нет.

## Сообщение с телефона в открытую вкладку VS Code

```mermaid
sequenceDiagram
  autonumber
  actor You as Ты, с телефона
  participant D as pultd
  participant W as обёртка вкладок
  participant CC as Claude Code
  participant X as расширение VS Code
  You->>D: «теперь тесты» (тема или приложение)
  D->>W: сообщение пользователя для этой сессии
  Note over W: между двумя строками расширения
  W->>CC: одна строка stream-json в stdin
  CC->>X: повторяет её (--replay-user-messages)
  Note over X: вкладка показывает её как твоё сообщение<br/>и ход, который оно начинает
  CC-->>D: хуки как обычно: шаги, Stop с итогом
  D-->>You: итог — ответом на твоё сообщение
```

Всё остальное обёртка передаёт байт в байт. Она действует только на проверенных версиях Claude Code и только в
выбранных тобой папках. В любом другом случае (выключатель, незнакомая версия, любая ошибка до старта) она просто
запускает настоящий `claude` на своё место и исчезает. Вкладка, занятая ходом, получает сообщение посреди этого
хода: отдельным сообщением вкладка его не показывает, а ответ приходит с итогом того хода.

## Одна модель делает, другая проверяет

```mermaid
sequenceDiagram
  autonumber
  actor You as Ты, с телефона
  participant D as pultd
  participant CC as Claude Code<br/>(сессия с телефона)
  participant V as производитель исполнителя<br/>(Anthropic, DeepSeek…)
  participant CX as Codex<br/>(app-server)
  You->>D: «Новая задача» · кто делает: DeepSeek
  Note over D: проект разрешён другим производителям?<br/>ключ есть? Иначе ничего не запустится
  D->>CC: Agent SDK — с адресом производителя,<br/>твоим ключом и его моделями
  CC->>V: ходы — по собственному протоколу Claude Code
  CC-->>D: хуки как обычно: шаги, Stop с итогом
  D-->>You: итог — с «Второе мнение · Codex»
  You->>D: «Второе мнение»
  Note over D: твои слова, отчёт, файлы,<br/>коммит, на котором задача началась
  D->>CX: thread/start (только чтение, без вопросов),<br/>review/start — что изменилось
  CX-->>D: замечания: важность, место, что сделать
  D-->>You: карточка Codex в конце сессии
  You->>D: «Отправить DeepSeek»
  D->>CC: замечания — твоим сообщением в ту же сессию
```

Сессия производителя — обычная сессия Claude Code с другим окружением: адрес производителя, твой ключ, его модели по
ролям (главная и быстрая — для заголовков и подагентов). Хуки, транскрипт, карточки и «чей ход» работают так же, как
с Claude. Она запускается только в разрешённом проекте и никогда без ключа: с адресом, но без ключа Claude Code отдал
бы туда твой вход в Claude (проверено на настоящем Claude Code).

Второе мнение — собственное ревью Codex. Пульт говорит ему, что изменила задача, — в git всё от коммита, на котором
стояла папка в начале задачи, новые файлы тоже; без git — файлы, которые записали правки Claude, — и добавляет твои
слова и отчёт Claude, чтобы сделанное нарочно не сочлось ошибкой. Codex читает в песочнице только для чтения, ничего
не спрашивает и хранит ревью в своей истории; версию Codex, на которой Пульт не проверен, он сначала сверяет с
собственной схемой протокола Codex.

## Веб-приложение: посредник, который ничего не хранит

```mermaid
sequenceDiagram
  participant P as Mini App (телефон)
  participant R as посредник (твой сервер)
  participant D as pultd (твой компьютер)
  D->>R: wss /pult/agent, с общим секретом (наружу)
  P->>R: wss /pult/ws, с initData от Telegram
  Note over R: подпись Telegram (Ed25519)<br/>и твой ID — чужие отсекаются здесь
  R->>D: вход, передаётся дальше
  Note over D: снова проверяет initData токеном бота:<br/>не старше 10 минут или одноразовый ключ переподключения
  D-->>P: данные экрана — в момент запроса
```

Посредник данных не хранит: каждый экран приходит с компьютера, когда ты его открываешь. Страница загружает скрипты
только с твоего сервера и Telegram (Content-Security-Policy), а компьютер сверяет файлы, которые отдаёт сервер, с
выложенными — или с выпуском, который сервер взял сам, — и закрывает приложение при расхождении (`PULT_GUARD=warn` —
только предупреждение, для CDN, который меняет файлы).

## Темп расхода: как считается кривая

Экран «Ресурсы» показывает каждый лимит (неделю, окно 5 ч) от начала до сброса — против ровного темпа, с прогнозом
при нынешнем темпе и с тем, сколько сессий работало одновременно.

```mermaid
flowchart LR
  G["get_usage<br/>(Claude Code, без запроса к модели)"] -->|"целые проценты,<br/>раз в 15 мин при работе"| L[("usage_log")]
  T[("транскрипты:<br/>каждый ответ модели<br/>с его токенами")] --> S["5-минутные ячейки:<br/>вес по моделям и проектам,<br/>сессии и агенты в работе"]
  L --> C["кривая проходит<br/>через каждое показание"]
  S --> C
  C --> F["прогноз по темпу<br/>последних суток / часа"]
  F --> V["в темпе · недобор · перебор<br/>+ сколько часов работы сессии осталось"]
  V --> UI["график в приложении,<br/>значок на «Главной»"]
```

- **Процент — правда.** Он приходит из собственного запроса Claude Code `get_usage`: около двух секунд, без
  запроса к модели. Каждое показание хранится 60 дней.
- **Форма между двумя показаниями — по транскриптам.** Ответ весит
  `вход + R·чтение кэша + 1,25·запись в кэш (2 для часового кэша) + 5·выход` — соотношения цен API, R — своё у модели:
  0,05 у Opus 5.5, 0,025 у Fable 5.1, 0,1 у остальных — на множитель своей модели. Множитель Fable подбирается по доле
  недели, которую потратил Fable: её сообщает `get_usage`; «На Fable — примерно в N раза дороже» сравнивает ту же работу —
  токены Fable с тем, сколько они весили бы по цене чтения Opus.
  Прирост между двумя показаниями раскладывается по ячейкам пропорционально весу, поэтому кривая проходит через
  каждое показание, даже если подписка взвешивает токены иначе. Прирост без токенов на этом компьютере виден как
  «не на этом компьютере».
- **Сессия в работе** — от твоего сообщения до конца её хода (`end_turn`); пауза внутри хода до 30 минут (долгая
  команда) тоже считается работой. Агенты считаются отдельно.
- **Цена:** первое чтение недели транскриптов — около 2 с (замер — 1,15 ГБ); дальше читается только дописанное
  (~20 мс). Ответ приложению — ~6 КБ.

## Что никогда не ломает твой Claude Code

| Правило | Как |
|---|---|
| Хук никогда не мешает | нет демона, тайм-аут, любая ошибка — выход 0 без вывода |
| Обёртка никогда не мешает | при любом сомнении — настоящий `claude` на её место; данные идут байт в байт |
| Обновление Claude Code не сломает вкладки | на непроверенной версии запись во вкладки выключается сама, и Пульт говорит об этом |
| Ответы не зависают | хук разрешения и окно идут наперегонки; решает первый ответ |
| Код проекта уходит другому производителю только там, где ты разрешил | спрашивает раз на проект — при первом выборе производителя или первом втором мнении; «Запретить» на экране проекта забирает разрешение и останавливает его сессии производителей и ревью |
| Без ключа нет сессии производителя | Claude Code с адресом производителя и без ключа отдал бы туда твой вход в Claude, поэтому такое окружение Пульт не собирает вовсе |
| Перезапуск не убивает работу | `pult restart` / `stop` / `install.sh` отказывают, пока сессии с телефона заняты (`pult busy`) |
| Компьютер закрыт | Telegram — long polling; посредник — исходящий WebSocket; слушающих портов нет |
| Настройки остаются твоими | хуки ложатся в `~/.claude/settings.json` с резервной копией; `pult hooks off` и `pult uninstall` всё откатывают |
| Файл уходит только из своего проекта | `pult send` и «В Telegram» берут только файлы внутри папки проекта сессии (после разворота ссылок), ничего похожего на ключи и настройки, до 50 МБ; только в твою группу |
| Новый проект ничего не перезаписывает | только новая папка внутри домашней; занятую Пульт отклоняет, как и имя, которое Claude Code спутает с другим проектом; клон доходит до git только ссылкой https |
| Обновление ставит только закоммиченное | «Поставить» в приложении берёт файлы самого Пульта из коммита, на котором стоит его папка (а в клоне репозитория Пульта — из новейшего выпуска, скачанного с GitHub), — никогда незакоммиченные правки; если перезапуск оборвёт сессии с телефона, сначала спросит; новая версия не поднялась — вернётся прежняя |
| Компьютер не получает власти над сервером | компьютер только называет выпуск, на котором стоит; обновлятель на сервере берёт этот выпуск с GitHub — официальный и не старше своего — от учётки, которой принадлежит только код посредника, и сам возвращает прежний, если посредник не поднялся (`deploy/relay/update.py`) |

## Карта кода

| Файл | Роль |
|---|---|
| `src/pultd.py` | демон: события, сессии, Telegram, предупреждения |
| `src/pult_api.py` | что спрашивают экраны приложения — «Главная», проекты, сессия, новый проект, файлы, голос, расход, настройки: обработчики их запросов, часть самого демона (примесь его класса); настройки демона они читают через сам демон |
| `src/pult_parts.py` | части Пульта и его обновления — экран «Пульт и его части» в настройках и то, что держит Пульт свежим: обновление из приложения, сервер вслед за компьютером, выпуски на GitHub, каждая часть против поставленного, проверка версии Claude Code, которую скачал VS Code; примесь класса демона, как `pult_api` |
| `src/pult_driven.py` | сессии, которые Пульт ведёт сам через Agent SDK, — новые, продолженные и копии, их место среди ходов, идущих сразу, хуки, которые Пульт в них ставит, — и что Пульт держит о каждой живой сессии |
| `src/pult_tg.py` | связь демона с Telegram — клиент Bot API (сначала через прокси, при сбое напрямую) и очередь, через которую каждое сообщение идёт в пределах ограничений Telegram, — и его база состояния |
| `src/pult_hook.py` | хук: событие — демону, решение — обратно; только стандартная библиотека |
| `src/pult_tab.py`, `src/pult-tab.sh` | обёртка вкладок и её запуск |
| `src/pult_tabcheck.py` | проверка версии Claude Code, которую скачал VS Code, на твоём компьютере — до того, как окно перейдёт на неё: обёртка, сообщение с телефона, модель, раздумья и гонка разрешений на программе `claude` новой версии (`pult tab check`) |
| `src/pult_codex.py` | второе мнение Codex: находит Codex и сверяет его версию с его же схемой протокола, собирает, что было в задаче (твои слова, итог Claude, файлы, коммит на её начале), проводит одно ревью только для чтения через протокол `app-server` и разбирает замечания |
| `src/pult_vendors.py` | модели других производителей внутри Claude Code: профиль каждого (адрес, модели по ролям, окно сжатия, советы, цена), окружение сессии — никогда без ключа владельца — и проверка ключа |
| `src/pult_web.py` | связь с посредником, проверка входа, транскрипты для приложения |
| `src/pult_render.py`, `src/pult_i18n.py` | как выглядят сообщения; все видимые строки по-английски и по-русски |
| `src/pult_attn.py`, `src/pult_brief.py` | «чей ход»: итог каждой сессии; строка итога маленькой моделью (по желанию) |
| `src/pult_tags.py` | теги задач: раздел проекта и тема в нём у каждой задачи — ведёт та же маленькая модель по запросу, ответу Claude и файлам задачи; человек только поправляет |
| `src/pult_spend.py` | темп расхода: транскрипты в ячейках, кривая, прогноз |
| `src/pult_load.py` | нагрузка каждой сессии на компьютер по одному снимку процессов |
| `src/pult_new.py` | новый проект: имя папки из любого названия, проверки, ссылка для клона |
| `src/pult_files.py` | файлы с телефона и на телефон: имена, входящие проекта, что можно отправить, файлы хода, архивы |
| `src/pult_update.py` | обновление из приложения: что в папке новее (в клоне репозитория Пульта — выпуски на GitHub), установщик с откатом, история; насколько каждая часть (копия на сервере — по её файлам) отстаёт от ветки |
| `src/pult_os.py` | всё, что различается на macOS, Linux и Windows |
| `src/pult_stt.py` | голос в текст (Groq Whisper, твой ключ) |
| `src/pultctl.py`, `src/pult_setup.py` | команда `pult`; установка, мастер, отчёт, удаление |
| `relay/relay.py`, `relay/web/` | посредник и Mini App (Preact + htm, без сборки) |
| `deploy/relay/` | посредник на твоём сервере: `install.sh`, его службы systemd, `update.py` — обновлятель, который берёт выпуск компьютера с GitHub |

## Где что лежит

| Что | Где |
|---|---|
| код и его окружение Python | `~/.local/share/pult/` (туда копирует установщик) |
| состояние: темы, сессии, итоги, файлы ходов, показания расхода | `~/.local/share/pult/state.db` (SQLite) |
| секреты: токен бота, твой ID, секрет посредника, ключ голоса, ключи производителей | `~/.config/pult/env`, права 600; ключ производителя приложение кладёт или убирает, но обратно не читает |
| ревью Codex | собственная история Codex (`~/.codex/sessions`), как у любой твоей задачи |
| хуки | `~/.claude/settings.json`, записи с `pult_hook.py` |
| обёртка вкладок | настройка VS Code `claudeCode.claudeProcessWrapper` (строку добавляешь ты) |
| журналы | `~/Library/Logs/pult.log` (macOS), `~/.local/state/pult/pult.log` (Linux, Windows) |

## Проверки

- `tests/test_pult.py`, `test_setup.py`, `test_web.py`, `test_relay.py` идут без Telegram и Claude: поддельный
  Bot API, настоящий посредник, выдуманные транскрипты. GitHub Actions гоняет их на macOS, Ubuntu и Windows.
- `tests/e2e_live.py` ведёт настоящего Claude (haiku) через всю цепочку; тратит немного подписки.
- `tests/fake_codex.py` заменяет Codex в проверках и на стенде: говорит по протоколу `app-server` и находит два
  замечания.
- `tests/probe_*.py` перепроверяют факты о Claude Code, на которых держится Пульт (гонка хука и окна, поток
  обёртки, фоновые задачи, что уходит на адрес производителя…). Их перезапускают после каждого обновления Claude Code, и запись во вкладки на новой
  версии разрешается только после того, как они прошли.
